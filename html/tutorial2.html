01

O menu que some ao rolar

A barra do topo é transparente por cima do vídeo da capa. Assim que a pessoa rola, ela desliza pra cima e sai da tela; quando volta pro topo, ela volta deslizando.

O código script.js — parte 1 
const menu = document.getElementById("menu");

window.addEventListener("scroll", function () {
  // depois dos primeiros 50px, o menu sai da tela.
  // volta sozinho quando a pessoa chega no topo de novo.
  if (window.scrollY > 50) {
    menu.classList.add("menu-rolado");
  } else {
    menu.classList.remove("menu-rolado");
  }
});
O código style.css — o menu ganha 2 coisas 
.menu {
  /* ...tudo o que já estava aqui da Live 2... */
  transition: transform 0.3s ease;
}

.menu-rolado {
  transform: translateY(-100%);
}
document getElementById addEventListener "scroll" window.scrollY if / else classList transition
ACHAR
document é a página inteira, vista por dentro pelo JavaScript. getElementById("menu") procura um elemento pelo id que ele tem lá no HTML — aquele <nav class="menu" id="menu"> da Live 1. O const guarda o achado numa caixinha pra não precisar procurar de novo.
ESCUTAR
addEventListener é “fica de olho e me avisa”. O primeiro pedaço é o quê ("scroll"), o segundo é o que fazer quando acontecer. Essa função entre parênteses roda dezenas de vezes por segundo enquanto a pessoa rola.
scrollY
window é a janela do navegador. window.scrollY é quanto a pessoa já rolou, em pixels — no topo vale 0. Põe um console.log(window.scrollY) lá dentro, abre o Console (F12) e rola: dá pra ver o número correndo.
if / else
if é “se”. else é “senão”. Os dois são obrigatórios aqui: só com o if, o menu sai da tela e nunca mais volta, porque ninguém manda remover a classe.
transition
translateY(-100%) significa “sobe a sua própria altura”, ou seja, some pra cima. Quem faz isso ser suave é o transition: transform 0.3s ease no .menu — sem ele o menu some de um frame pro outro.
Atenção
Nada disso funciona se o <script> não estiver no fim do <body>. O navegador lê a página de cima pra baixo: se o script rodar antes, o <nav id="menu"> ainda não existe e o getElementById devolve null.

Os blocos que aparecem subindo

Os textos das seções começam invisíveis e um pouquinho pra baixo. Quando entram na tela, sobem com fade. Quem avisa que eles entraram é o IntersectionObserver.

O código index.html — a classe entra em 2 lugares 
<!-- sempre na <div> de dentro, nunca na <section> e nunca no rodapé -->
<section class="secao-historia">
  <div class="conteudo-central aparecer"> ... </div>
</section>

<section class="secao-video">
  <div class="conteudo-central aparecer"> ... </div>
</section>
O código script.js — parte 2 
const blocos = document.querySelectorAll(".aparecer");

const observador = new IntersectionObserver(function (entradas) {
  entradas.forEach(function (entrada) {
    if (entrada.isIntersecting) {
      entrada.target.classList.add("visivel");
      observador.unobserve(entrada.target);
    }
  });
}, { threshold: 0.15 });

// manda o observador vigiar cada um dos blocos da lista
blocos.forEach(function (bloco) {
  observador.observe(bloco);
});
O código style.css — o antes e o depois 
.aparecer {
  opacity: 0;
  transform: translateY(30px);
  transition: opacity 1s ease-out, transform 1s ease-out;
}

.aparecer.visivel {
  opacity: 1;
  transform: translateY(0);
}
querySelectorAll IntersectionObserver forEach isIntersecting unobserve threshold
um × todos
getElementById traz um elemento. querySelectorAll(".aparecer") traz todos que têm aquela classe — vem uma lista. Por isso precisa do forEach: pra falar com cada um, um de cada vez.
observador
IntersectionObserver é um vigia que o próprio navegador oferece: você entrega elementos pra ele e ele avisa quando eles entram ou saem da tela. Cada aviso vem como uma entrada, e entrada.isIntersecting responde “está aparecendo agora?”.
unobserve
unobserve é “pode parar de vigiar esse aqui”. Sem ele nada quebra — mas o observador continua trabalhando à toa pra sempre, num bloco que já apareceu e não vai voltar atrás.
threshold
threshold: 0.15 quer dizer “me avisa quando 15% do bloco estiver visível”. Com 0 avisa no primeiro pixelzinho; com 1 só quando o bloco inteiro couber na tela.
Atenção
A classe aparecer vai na <div class="conteudo-central"> de dentro, e em exatamente 2 lugares. Na <section> não funciona bem: ela ocupa a tela toda, “entra na tela” cedo demais e a animação dispara antes de a pessoa chegar no texto.

03

O vídeo da capa que anda com o scroll

A capa fica presa na tela, o conteúdo dela some, o vídeo aparece por trás e o tempo do vídeo passa a ser controlado pelo dedo da pessoa. Aqui entra a primeira biblioteca da nossa vida: o GSAP.

O código script.js — parte 3 
gsap.registerPlugin(ScrollTrigger);

const video = document.querySelector(".capa-video");

function animarCapa() {
  const linhaDoTempo = gsap.timeline({
    scrollTrigger: {
      trigger: ".capa",
      start: "top top",
      end: "+=2500",
      scrub: 1,
      pin: true
    }
  });

  linhaDoTempo.to(".capa-conteudo, .capa-barra, .capa-seta", {
    opacity: 0,
    scale: 0.6,
    duration: 0.1
  }, 0);

  linhaDoTempo.to(video, { opacity: 1, duration: 0.8 }, 0);

  linhaDoTempo.to(video, {
    currentTime: video.duration,
    duration: 1,
    ease: "none"
  }, 0);
}

// se o navegador já leu o vídeo, roda agora. se não, espera ele ler.
if (video.readyState >= 1) {
  animarCapa();
} else {
  video.addEventListener("loadedmetadata", animarCapa);
}

gsap.registerPlugin querySelector function gsap.timeline scrollTrigger scrub pin currentTime loadedmetadata
Biblioteca
Biblioteca é código pronto que alguém escreveu, testou e liberou pro mundo. O GSAP faz animação. Você não “instala” nada: cola duas tags <script> de CDN no HTML e as palavras gsap e ScrollTrigger passam a existir dentro do nosso arquivo.
function
function animarCapa() { ... } é uma receita guardada com nome. Escrever a receita não executa nada — ela só roda quando alguém chama animarCapa(). Aqui ela é chamada num de dois momentos possíveis, lá embaixo.
scrub / pin
pin: true prega a capa na tela enquanto a cena roda. scrub: 1 amarra a animação ao scroll, com 1 segundo de atraso macio. E ease: "none" faz o vídeo andar na mesma velocidade do dedo — sem isso ele acelera e freia sozinho.
Armadilha
display: none × opacity: 0. O .capa-video estava com display: none desde a Live 2. display: none não é invisível, é inexistente: o GSAP anima a opacidade dele e não acontece nada na tela — e sem nenhum erro no console pra te dar pista. Por isso a regra é trocada, não complementada.
Armadilha
video.duration vem NaN se o código rodar antes de o navegador ler o arquivo (NaN = “isso não é um número”). Daí o if (video.readyState >= 1) ... else loadedmetadata: o if cobre o F5 com o vídeo em cache, o else cobre o primeiro acesso.

04

O acabamento: a memória de scroll

Faltam duas linhas no começo do arquivo. Sem elas, quem der F5 no meio da cena da capa cai numa página quebrada — e é o tipo de bug que só aparece depois que tudo já estava funcionando.

O código script.js — as duas primeiras linhas 
/* ============================================================
   GTA VI — COMPORTAMENTO DA PÁGINA (JavaScript)
   ============================================================ */

// Sempre começar a página no topo (o pin da capa depende disso).
// O ScrollTrigger tem a memória DELE, separada da do navegador — limpa as duas.
ScrollTrigger.clearScrollMemory("manual");
window.scrollTo(0, 0);
ScrollTrigger.clearScrollMemory window.scrollTo
Armadilha
A memória de scroll é dupla. Mandar só history.scrollRestoration = "manual" não resolve: o ScrollTrigger guarda a posição dele por conta própria e sobrescreve a configuração do navegador. Quem resolve é ScrollTrigger.clearScrollMemory("manual").
Ordem
Essas linhas ficam no começo do arquivo, antes de tudo. O pin da capa calcula as posições a partir de onde a página começou — se ela começar no meio, a conta sai errada e os blocos ficam sobrepostos.
Repara
Esse bug não aparece enquanto você está construindo, porque você entra na página sempre pelo topo. Ele aparece na primeira vez que você dá F5 no meio do teste — normalmente ao vivo, na frente de todo mundo.
Rodando parte 04 de 05
Capa inteira, do topo A página recomeçou em scrollY = 0. O pin calcula as posições certas e a cena roda inteira.
Cena quebrada A página voltou em scrollY = 1840, no meio do pin. A capa aparece sobreposta ao texto e o vídeo trava num frame do meio.

Aperta os dois botões e compara. O navegador é gentil: ele tenta te devolver onde você parou. Numa página com pin, essa gentileza é justamente o problema.

Leitura
Lê de cima pra baixo uma vez só, sem tentar entender tudo. O que você quer enxergar é o desenho: acabamento, funcionalidade 1, funcionalidade 2, funcionalidade 3. Cada bloco começa achando um elemento e termina trocando alguma coisa.
Se não rodar
Abre o Console (F12) e lê a primeira mensagem vermelha, não a última. gsap is not defined = ordem dos <script>. Cannot read properties of null = o id ou a class não bate com o HTML.
Próximo passo
Muda os números e vê o que acontece: troca o 50 por 300, o threshold por 0.8, o end por "+=1200". Quebrar de propósito e consertar é como se aprende programação de verdade.
